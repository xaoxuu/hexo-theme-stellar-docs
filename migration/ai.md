把本页与站点仓库、目标主题源码一起交给 AI，用于从已发布 v1 迁到 v2。迁移字段规则由[配置对照表](/wiki/stellar/migration/fields/)维护，本页列出执行步骤和每步需要确认的结果。

## 1. 确认版本和操作范围

读取各仓库的 AGENTS.md、实际安装版本和工作区差异。记录输入发布版本、目标 commit、Node/Hexo、主题安装方式、站点构建命令，以及明确获准的目录与外部动作。

完成条件：可以区分原有工作与本次迁移；源码、站点、文档及子模块引用各有明确所有者。版本不明时先查锁文件与 Git，不猜测。

## 2. 对照新旧配置

盘点主题覆盖、Collection、Front Matter、自定义模板／脚本、后处理和旧 URL。每个旧字段记录所在文件、用途、目标字段或移除理由；对照原版本源码确认旧字段用法，再从目标版本的默认配置、Schema 和实际实现核实新用法。

完成条件：每项实际使用的输入有去向；路由、归属、评论线程、图片来源和被移除能力的未决项单独列出。身份或含义有歧义时请求必要信息，继续处理不依赖答案的部分。

## 3. 修改配置与内容

按配置作用域编辑，保留第三方参数原名、原内容日期、有效自定义和用户修改。数组转换需保留顺序及明确清空意图。普通文章和页面不强行创建 Collection；现有归属与路由只在证据支持时改变。

完成条件：目标输入可由当前 Schema 和 profile 解析；旧字段只在有意保留的历史正文或迁移说明中出现。不为开发期间的中间配置增加兼容处理，不根据猜测设置默认值或添加没有实际用途的代码。

## 4. 检查配置与页面

严格运行 Doctor，修正全部 issues 并逐项处理 warnings；随后执行站点实际构建。对受影响内容类型检查路由、导航、封面、搜索与评论。宿主有 Babel／压缩时验证 Runtime 原生 ESM；URL 变化时检查跳转、hash、canonical 与索引。

完成条件：为受影响的功能提供检查结果，列出命令和检查场景。未运行的浏览器、安装或部署检查明确写为未验证；构建容错不能代替 Doctor 通过。

## 5. 汇报结果与回退方法

提供本次文件清单、重要语义变化、验证结果、待决项和可执行的回退依据。按用户已有授权处理提交、推送、部署或 Issue 回写；各仓库分别交付，子模块源码变更与宿主引用变更分别授权。

完成条件：说明已完成和受阻的事项，以及恢复原站的方法。外部写入须已获授权；迁移检查通过与正式发布分别报告。
